# Wooya — MVP Spec

> 状态：已评审定稿（2026-11-15）。
> 本文回答「做什么、做到什么程度算完成」；实现细节在 Impl 阶段另行产出。

## 1. Intent（意图）

**一句话定位**：一个可脱离任何 IDE 运行的本地学习资料 agent——收录资料、双轨回答（模型自答 + 库内对照）、以苏格拉底问答记录学习者的理解输出。数据本地优先，能力可扩展。

**目标用户**：所有自学者；像 Claude Code 一样安装使用（npm 全局安装或 npx），`wooya init` 指定自己的资料目录即可开始。

**核心价值（v2 重审，按优先级）**：

1. **主权与可扩展**：资料与学习记录留在本地（markdown + JSON，格式开放），未来可自行接云同步；检索策略按资料类型可插拔注册，学习流程可自定义扩展。
2. **双轨回答**：LLM 给出自己的回答，同时核对库内资料进行对比——一致、冲突、补充分别标注；库内缺料时指引用户收录。模型能力与本地资料互相校验，而不是二选一。
3. **学习输出沉淀**：学习的证据是学习者本人的输出（对知识的提取与应用）。MVP 以苏格拉底问答引出用户输出并整段存档，为未来的反馈修正闭环提供原料——用户有输出，才谈得上反馈。

**非目标（MVP 明确不做）**：

- 对用户回答的评分与纠错——二期（苏格拉底模式只通过追问推进，不给判定）
- 学习路径规划、遗忘复习——二期
- 云同步、Web UI、多用户
- embedding / 语义检索（留二期）
- 会话持久化、断点续传

## 2. 入口形态（会话优先，参照 Claude Code）

核心是**同一个 agent loop**，入口只差「输入怎么来、循环要不要退出」：

| 入口 | 形态 | 行为 |
| --- | --- | --- |
| `wooya`（默认） | 交互式 REPL | 多轮会话；收资料、提问、学习问答都是会话内自然意图，支持 `/add`、`/sources`、`/provider`、`/model`、`/learn`、`/clear` 斜杠命令；上下文跨轮保留；`/provider` 登记与切换 API 供应商，`/model <id>` 切换会话模型 |
| `wooya ask "<问题>"` | 单发 | 不进会话，跑一轮 loop，给出双轨回答后退出 |
| `wooya add <url\|repo\|file>` | 单发 | 执行收录流水线后退出 |
| `wooya init` | 单发 | 在当前目录生成 `.wooya/config.json`（指向 `sources/`、`outputs/` 等） |

架构约束：「读输入」抽象为会话状态（单发 = 一次输入，REPL = 循环读 stdin + 斜杠命令解析），loop 本体完全复用。

### 用户故事

**US-1 收资料**（`add`，会话内意图或单发）：

- 网页 URL → 抓取正文转 markdown 存入 `sources/`；GitHub 仓库 URL → `git clone` 并**记录 commit SHA**；本地文件 → 复制（不移动）进 `sources/`。
- 每份资料生成元数据（来源、类型、收录时间、SHA/URL），登记进清单文件；重复收录提示而非静默覆盖。
- 收录后 agent 不修改 `sources/` 内任何文件（原始资料只读）。

**US-2 双轨提问**（`ask`，会话内意图或单发）：

- 回答固定两段：
  - **【模型回答】**：LLM 自身的最佳回答；其中未经库内资料支持的论断标注「未经库内核对」。
  - **【库内对照】**：基于检索结果，标注与模型回答**一致 / 冲突 / 补充**三类关系，库内内容引用 `sources/<路径>:<行号>`；库内无相关资料时明确说明「无资料可对照」。
- 缺料指引：当问题明显依赖某类资料而库内没有时，提示用户可用 `wooya add` 收录，并说明缺的是哪类资料。
- 检索过程：模型生成关键词 → grep → 读片段 → 可迭代换词（≤ 5 轮）→ 组织回答。

**US-3 学习问答**（`/learn <概念>`，仅会话内）：

- 用户输入 `/learn <概念>` 后，agent 以**苏格拉底式导师**角色展开：围绕该概念持续向用户提问，用户逐轮回答；agent 通过追问推进理解，不评分、不直接给标准答案。
- 问答过程对用户实时可见；用户输入 `/end` 结束后，整段问答记录存档为 `outputs/<日期>-<概念>.md`，frontmatter 记录概念、时间、关联来源（检索到的相关 `sources/` 路径，可为空）。
- 记录中用户回答**原话保留**，AI 不润色、不改写、不补全；agent 提问属 AI 生成内容，与用户回答明确区分（谁说的可辨）。
- 写入前向用户展示存档内容并确认。

## 3. 架构

```
CLI (wooya) ──► 会话状态（单发=一次输入 / REPL=循环读stdin + 斜杠命令解析）
                    │
                    ▼
              Agent Loop（自建）
                │  组装 system prompt + 工具定义 + 消息历史
                │  循环：LLM 响应 → 工具调用 → 结果回填 → 直至产出最终回答
                │  上下文裁剪：工具输出截断（片段行数上限）→ 超长丢弃并告知模型 → 历史滑动窗口
                ▼
             Tools（「输入 JSON → 输出 JSON」函数签名；预留独立进程扩展点）
                ├─ grep_search  : 在 sources/ 内按关键词检索，返回 文件:行号 + 命中行
                ├─ read_source  : 读取某文件指定行范围
                ├─ list_sources : 列出已收录资料及元数据
                └─ (ingest 内部工具：fetch_url / git_clone / copy_file，仅收录用)
```

- **Agent loop 自建**：不依赖 agent 框架；LLM 调用使用 openai-node 客户端库（OpenAI-compatible 单协议，baseURL 可指向任意兼容供应商）。
- **LLM 接入**：OpenAI-compatible 单协议；客户端库 openai-node。配置不走环境变量，解析优先级：数据目录 `.wooya/config.json` 的 `provider` 指名 > 用户级 `~/.wooya/providers.json` 的 `active` > 内置默认。用户级注册表中一个 provider 条目 = 一个连接（baseUrl / apiKey / maxTokens）+ 一组模型（`models` 列表与 `defaultModel`，由 `/provider model <name> add|remove|default` 维护）；`/provider` 管连接、`/model` 管当前 provider 内的模型切换（key 明文存储，二期接系统凭证），`wooya init` 保持无交互。
- **错误恢复**（三类必做）：add 流水线的输入校验与失败提示（网络失败 / clone 失败 / 重复收录）；LLM 调用重试（超时、429 指数退避）；工具抛错时错误信息回填给模型自行调整。
- **最小观测**：每轮 loop 的工具调用、耗时、token 用量写本地日志；`--verbose` 输出到终端。

## 4. Agent 能力维度与 MVP 取舍

| 维度 | MVP 判定 | 说明 |
| --- | --- | --- |
| 工具调用 | ✅ 必做 | loop 本体；同进程 JSON 函数调用 |
| 模型适配 | ✅ 必做（收窄） | 仅 OpenAI-compatible 单协议；多协议 adapter 留二期 |
| 上下文管理 | ✅ 必做（最小版） | 工具输出截断 + 滑动窗口；无裁剪则 agentic search 一轮即爆上下文；自动压缩留二期 |
| 会话状态 | ✅ 必做（最小版） | 内存消息历史 + `/clear`；持久化/恢复留二期 |
| 规划 | ❌ 不做 | 单层检索-阅读-回答循环；学习循环二期再引入 |
| 评估观测 | ⚠️ 部分 | 本地日志 + `--verbose`；自动评估（引用准确率、golden set）留二期 |
| 约束与恢复 | ⚠️ 部分 | add 校验 / LLM 重试 / 工具错误回填三项必做；断点续传、会话回滚留二期 |

## 5. 数据契约

| 契约 | 内容 |
| --- | --- |
| sources 只读 | 收录后 agent 不修改 `sources/` 内文件 |
| SHA 固定 | 仓库类资料记录 commit SHA，引用时可指明版本 |
| 双轨标注 | 模型回答与库内证据必须可区分；库内引用格式 `sources/<相对路径>:<行号>` |
| outputs 原话 | 问答记录中用户回答原话保留，AI 不润色不改写；agent 提问与用户回答明确区分；写入前确认 |
| 可扩展 | Retriever 按资料类型可插拔注册；存储格式开放（markdown + JSON） |

**目录布局**：代码仓库与资料仓库分离。`wooya init` 在资料目录生成 `.wooya/config.json`，资料目录结构：

```
<资料目录>/
  sources/        # 原始资料（只读）
  outputs/        # 用户学习输出（原话存档）
  .wooya/config.json
```

## 6. 检索设计

- **`Retriever` 协议**：输入（query、source 上下文）→ 输出（带出处的片段列表）。按资料类型可插拔注册——这是核心价值 1 的落点。
- **MVP 唯一实现：grep 式检索**。优先系统 `ripgrep`，不可用回退内置 JS 遍历 + 逐行匹配。
- 词汇漂移靠 agentic search（模型换词迭代）弥补；embedding 留二期。

## 7. MVP 范围

| 做 | 不做 |
| --- | --- |
| REPL 会话 + 斜杠命令（`/add` `/sources` `/learn` `/clear`） | 会话持久化、断点续传 |
| `ask` 单发 + 会话内双轨回答 | 对用户回答的评分与纠错（二期） |
| `/learn` 苏格拉底问答 + 记录存档（写入前确认） | 学习路径规划、复习 |
| `add` 三条通路（URL / 仓库 / 文件）+ 元数据清单 | 增量索引（无索引层） |
| `init`、上下文裁剪、LLM 重试、本地日志 | Web UI、云同步、embedding |

## 8. 验收标准

1. Node ≥ 20，`npm i -g` 或 `npx` 可运行。
2. 空库提问：给出模型回答，且【库内对照】明确「无资料可对照」并给出 add 指引，而非编造出处。
3. `add` 分别收一份网页、一个 GitHub 仓库、一个本地文件，元数据完整，仓库记录 SHA。
4. 对已收录资料提问：回答含【模型回答】与【库内对照】两段，对照部分含至少一处 `sources/...:行号` 引用，引用行经人工核对与论断相符。
5. `/learn` 学习问答：agent 连续提问、用户逐轮回答；`/end` 后 `outputs/` 内生成问答记录，用户回答与输入逐字一致，提问与回答明确区分。
6. REPL 多轮会话中，前文提及的资料可在后续提问中被引用。
7. 除 LLM API 调用与收录抓取外，运行期不产生网络请求。
8. 收录后手工改动 `sources/` 内文件，提问不报错（以磁盘现状为准），元数据不回写修改。
9. 工具输出超长时被截断，会话不因上下文溢出中断。

## 9. 技术决策记录

| # | 决策 | 理由 | 备选与放弃原因 |
| --- | --- | --- | --- |
| D1 | 独立 CLI/agent 形态 | 脱离宿主 IDE，数据与能力可移植 | workspace+skills（绑定宿主）；Web 应用（工作量过大） |
| D2 | 自建 agent loop | MVP 只需单层工具循环，框架是负债；LLM 客户端库 openai-node 只做 API 适配，不属于框架 | Claude Code skill（仍绑宿主）；agent 框架（超出需求） |
| D3 | 框架层 Node/TS | 轻量、跨平台、CLI 分发成熟；tool 层保留多语言扩展点 | Python（分发与打包不如 Node 顺手） |
| D4 | grep 式检索 + agentic search | 零索引基础设施、天然精确到行出处；词汇漂移由模型换词迭代弥补 | sqlite FTS5（需维护索引层）；embedding（外部依赖，留二期） |
| D5 | MVP 场景 = 收 + 问 + 学 | 苏格拉底问答是学习价值链的最小一环；评分与反馈修正留二期 | 收+问（无学习环节，学习价值主张不成立） |
| D6 | 会话优先 + 单发命令双入口 | 同一 loop 复用，REPL 保留上下文，单发可脚本化 | 纯子命令（无法多轮追问）；纯 REPL（不便自动化） |
| D7 | 双轨回答取代「只依据库内」 | LLM 通识与本地资料互相校验，单轨要么受限要么失去 grounding；缺料指引让收录成为自然动作 | 纯 grounded（库里没有就没法用）；纯模型回答（无对照价值） |
| D8 | 用户回答原话存档，AI 不润色 | 学习者的输出是提取与应用的证据，改写即失真；原话才支撑未来反馈修正 | AI 辅助整理（混淆「谁的理解」） |
